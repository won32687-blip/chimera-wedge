# 2. 런북: 중단·재개·오류·예산

명령은 모두 PowerShell, 저장소 폴더에서 실행한다.

## 멈추기 (세 방법 모두 같은 처리)
| 방법 | 언제 |
|---|---|
| 실행 창에서 `Ctrl+C` 한 번 | 진행 중인 호출 1건만 끝내고 멈춘다 |
| `Ctrl+C` 두 번 | 즉시 멈춘다 (진행 중 호출은 비용을 보수적으로 '사용함'으로 정산) |
| 다른 창에서 `.\.venv\Scripts\python -m chimera stop <run_id>` | 실행 창을 건드리기 어려울 때 |
| `data\live\runs\<run_id>\STOP` 파일 만들기 | 명령을 쓰기 어려울 때 |

멈추면 `STOPPED / USER_STOP`과 리포트 위치가 출력된다.

## 이어서 하기
```powershell
.\.venv\Scripts\python -m chimera status                # 최근 실행 목록
.\.venv\Scripts\python -m chimera resume <run_id>       # 멈춘 곳부터 이어서
```
- 이어 하기 전에 중단 흔적을 정리한다: 응답을 못 받은 시도는 `ERROR(INTERRUPTED)`, 실행 전 테스트는 `CANCELLED`, 열린 예산 예약은 보수적으로 정산. **자동 재실행은 하지 않는다.**
- 대상 프롬프트·명세를 바꿨다면 이어 하기는 거부된다 → 새로 `run` 한다 (판정 기준이 섞이지 않게).

## 멈춘 이유(stop_reason)별 대응
| 멈춘 이유 | 뜻 | 할 일 |
|---|---|---|
| NO_TARGETS_LEFT | 모든 불변조건 검사 완료 | 리포트 확인 |
| COMPLETED | 회귀 재실행 완료 | 리포트의 "회귀 재실행 결과" 확인 |
| BUDGET_EXHAUSTED | 다음 호출이 1회·하루 상한 또는 호출 수 상한을 넘김 | 하루 상한이면 다음 날, 1회 상한이면 `config.toml [limits]` 조정 여부 결정 |
| MAX_TESTS / MAX_WALL_TIME | 테스트 수·시간 상한 | 필요하면 `resume` 대신 새 `run` (상한은 run마다 적용) |
| USER_STOP | 사용자가 멈춤 | `resume` 가능 |
| CONSECUTIVE_ERRORS | 대상 호출이 연속 실패 (429·5xx·연결) | 잠시 뒤 `resume`. 리포트의 실행 시도 상태 확인 |
| ATTACKER_ERROR | WEDGE가 3턴 연속 계약에 맞지 않는 출력 | 리포트의 "WEDGE 출력 오류" 확인 → 인계 문서에 기록하고 보고 |
| PROVIDER_BLOCKED | 401/403/404: 키·권한·모델 이름 문제 | 키 확인(`check`), `config.toml`의 `model_id` 확인 |
| NOT_ALLOWED | 허용 목록 밖 대상, 다른 실행이 진행 중, 명세 변경 | 메시지대로 처리 |

## 오류 재시도 규칙
- 재시도: 429(요청 한도)·5xx·연결 오류·시간 초과만. 최대 3회, 대기 2초→4초→8초(+무작위), `Retry-After` 우선.
- 재시도 안 함: 401/403/404(→ 실행 BLOCKED), 400(→ 그 호출만 실패).
- 실행 오류는 **대상의 FAIL이 아니다.** 판정은 VERIFIER만 한다.

## 예산
- 호출 **전에** "입력 추정 + 출력 상한 전부"를 예약하고, 상한을 넘을 호출은 시작하지 않는다. 끝나면 실제 사용 토큰으로 정산한다.
- 하루 기준은 이 PC의 현지 날짜.
- 오늘 사용액: `.\.venv\Scripts\python -m chimera status` 맨 아래 줄.
