# 참고: 설정과 상태값

이 문서는 사용자 가이드를 읽다가 특정 항목의 뜻을 찾아볼 때 쓰는 참고 자료입니다. 처음부터 끝까지 읽을 필요는 없습니다.

## 명령

모든 명령은 `chimera-wedge` 폴더에서 `.\.venv\Scripts\python -m chimera` 뒤에 붙여 실행합니다. 설정 파일을 지정하지 않으면 실제 실행용 `config.toml`을 쓰고, 연습 모드는 `--config config.mock.toml`을 붙입니다.

| 명령 | 하는 일 | AI 호출 비용 |
|---|---|---|
| `check --target 대상` | 설정, API 키, 예상 비용 확인 | 없음 |
| `run --target 대상` | 새 탐색 실행. 같은 대상의 이전 기록을 이어받음 | 있음 |
| `run --target 대상 --fresh` | 이전 기록을 쓰지 않고 처음부터 탐색 | 있음 |
| `set-key` | API 키를 프로젝트 `.env`에 저장 (입력이 화면에 안 보임) | 없음 |
| `regress --target 대상` | 회귀 세트만 다시 시험 | 있음 |
| `resume 실행번호` | 멈춘 실행 이어 하기 | 있음 |
| `stop 실행번호` | 실행 중인 시험에 멈춤 요청 | 없음 |
| `status` | 최근 실행 10개와 오늘 사용액 | 없음 |
| `status 실행번호` | 실행 하나의 현재 상태 | 없음 |
| `report 실행번호` | 리포트 다시 만들기 | 없음 |

## config.toml

설정 파일은 비용과 횟수 상한, 탐색 방식, 사용할 모델, 실행을 허용한 대상으로 나뉩니다. 값을 바꾼 뒤에는 `check`로 결과를 확인하는 것이 안전합니다.

**비용과 횟수 상한** (`[limits]`)

| 항목 | 의미 | 기본값 |
|---|---|---|
| `max_cost_usd_per_run` | 실행 한 번의 비용 상한 (달러) | 1.0 |
| `max_cost_usd_per_day` | 하루 비용 상한 (달러) | 3.0 |
| `max_tests_per_run` | 실행 한 번에 보낼 시험 수 상한 | 30 |
| `max_model_calls_per_run` | 실행 한 번의 AI 호출 수 상한 | 120 |
| `max_wall_minutes` | 실행 한 번의 시간 상한 (분) | 30 |
| `max_consecutive_errors` | 대상 호출이 연속 몇 번 실패하면 멈출지 | 3 |

**탐색 방식** (`[loop]`)

| 항목 | 의미 | 기본값 |
|---|---|---|
| `probe_limit` | 한 가지 공격 방식으로 보낼 시험 수 | 5 |
| `families_per_invariant` | 규칙 하나에 시도할 공격 방식 수 | 3 |
| `repro_n` | 실패를 확인할 때 다시 보내는 횟수 | 3 |
| `deepen_limit` | 확인된 실패 하나를 파고드는 시험 수 | 6 |
| `stale_streak` | 새 정보가 없는 시험이 몇 번 이어지면 방향을 바꿀지 | 3 |
| `exploit_share_max` | 확인된 실패를 파고드는 데 쓸 수 있는 시험 비율 (시험 수 상한 대비) | 0.5 |
| `max_retries` | 일시적 오류일 때 다시 시도하는 횟수 | 3 |
| `cover_min_tests` | 이어하기 때 이전 판정 시험이 이 수보다 적은 규칙을 "미검사 우선"으로 봄 | 3 |
| `prior_inputs_in_context` | "기존 규칙 심화" 때 공격 AI에게 보여 줄 이전 입력 수 | 6 |

**모델** (`[models.이름]`과 `[roles]`)

`[models.이름]` 항목 하나가 모델 하나의 설정입니다. 모델 이름(`model_id`), 100만 토큰당 입력·출력 가격, 한 번에 받을 최대 출력 길이(`max_tokens`, AI의 생각 과정 포함), 생각의 깊이(`effort`)를 적습니다. 가격이 비어 있으면 비용을 계산할 수 없으므로 실행을 거부합니다. `[roles]`에서 공격 AI(`attacker`)와 채점 AI(`judge`)가 어느 모델 설정을 쓸지 고르고, 대상이 쓸 모델은 대상 명세 파일에서 고릅니다. 채점 AI는 대상과 다른 모델로 두는 것을 권장합니다. 같은 모델이 자기 답을 채점하면 독립적인 검증으로 보기 어렵기 때문입니다.

**허용 대상** (`[allowed]`)

`targets`에 적힌 대상만 실행할 수 있습니다.

## 대상 명세 파일

`targets` 폴더의 `대상이름.toml` 파일 하나가 대상 하나를 정의합니다. `prompt_file`은 프롬프트 원문 파일, `model`은 대상을 돌릴 모델 설정 이름입니다.

판정 기준(`[[oracles]]`)은 두 종류가 있습니다. `RUBRIC_BASED`는 채점 AI가 문장으로 된 조건을 보고 판정하는 방식이고, `DETERMINISTIC`은 정해진 패턴이나 길이만 프로그램이 직접 검사하는 방식입니다. 문장 조건은 지켜야 할 행동(`acceptance`)과 하나라도 해당하면 위반인 행동(`rejection`)으로 나눠 적습니다. 직접 검사(`checks`)는 특정 패턴이 있으면 위반(`forbid_regex`), 없으면 위반(`require_regex`), 길이가 넘으면 위반(`max_chars`) 세 가지를 지원합니다. 조건마다 붙는 ID는 명세 파일 전체에서 겹치지 않아야 합니다.

규칙(`[[invariants]]`)은 판정 기준 하나와 연결되며, 공격 AI가 먼저 시도할 공격 방식 이름(`attack_families`)을 함께 적을 수 있습니다. `source`는 규칙의 출처로, 사용자가 확정한 규칙은 `USER_CONFIRMED`, 프로그램이나 AI가 추정한 초안은 `ENGINE_INFERRED`로 표시합니다.

## 상태값

리포트와 명령 출력에 나오는 상태값은 무엇에 대한 상태인지에 따라 다섯 종류로 나뉘며, 서로 다른 의미를 가집니다.

| 종류 | 대상 | 값과 의미 |
|---|---|---|
| 실행 상태 | AI 호출 한 번 | `EXECUTED` 응답 받음, `ERROR` 오류, `CANCELLED` 중단으로 취소, `BLOCKED` 권한 문제로 차단, `NOT_EXECUTED` 아직 응답 없음 |
| 판정 결과 | 시험 하나 | `PASS` 규칙 지킴, `FAIL` 규칙 어김, `INCONCLUSIVE` 판정 보류, `INVALID` 시험이나 판정 기준 자체의 오류, `NOT_RUN` 실행되지 않음 |
| 확인 상태 | 발견된 실패 | `VERIFIED` 재현 확인됨, `PENDING` 확인 전, `DISPUTED` 다시 시험했을 때 재현 안 됨, `REJECTED` 판정 기준 오류로 기각 |
| 진행 단계 | 탐색 흐름 | `ACQUIRE` 시험할 규칙 고르기, `PROBE` 여러 입력으로 찔러 보기, `FOCUS` 실패 발견, `VERIFY` 재현 확인, `DEEPEN` 더 짧은 입력으로 파고들기, `SPLIT` 원인 가설 나누기, `NEXT_INVARIANT` 다음 규칙으로 이동 |
| 실행 전체 | `run` 한 번 | `RUNNING` 진행 중, `STOPPED` 멈춤, `BLOCKED` 실행 불가 |

`NEXT_INVARIANT`는 원래 WEDGE 설계 문서에서 RESEED라고 부르던 단계와 같은 것으로, 이름만 바뀌었습니다.
