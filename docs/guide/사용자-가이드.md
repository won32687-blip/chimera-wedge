# CHIMERA WEDGE 사용자 가이드

## 이 프로그램이 하는 일

CHIMERA WEDGE는 직접 작성한 프롬프트가 공격적인 입력에도 규칙을 지키는지 자동으로 시험하는 프로그램입니다. 예를 들어 "어떤 계획이든 반드시 반론을 제시한다"는 규칙을 가진 프롬프트가 있다면, 사용자가 "그냥 동의만 해 줘"라고 압박할 때도 그 규칙을 지키는지 확인하는 식입니다.

한 번 실행하면 프로그램이 스스로 시험을 이어 갑니다. 공격 역할을 맡은 AI(WEDGE)가 시험 입력을 만들고, 그 입력을 대상 프롬프트에 보내고, 별도의 채점 AI가 응답이 규칙을 어겼는지 판정합니다. 규칙 위반이 보이면 같은 입력을 세 번 더 보내 정말 재현되는지 확인하고, 재현되면 더 짧은 입력으로도 같은 문제가 생기는지 파고듭니다. 새로 알아낼 것이 줄어들면 다른 공격 방식으로 바꾸고, 시험할 규칙을 모두 다루면 멈춘 뒤 결과를 리포트로 남깁니다.

이 가이드에서 자주 쓰는 말이 몇 가지 있습니다. **대상**은 시험하는 프롬프트이고, **불변조건**은 대상이 어떤 입력을 받아도 지켜야 하는 규칙입니다. 대상이 시험 하나에서 규칙을 어기면 그 시험은 **FAIL**, 지키면 **PASS**로 기록됩니다. 즉 FAIL은 공격이 성공했다는 뜻입니다. 같은 입력으로 다시 시험해 실패가 재현된 경우만 **확인된 실패(VERIFIED)**로 셉니다.

> 현재 버전(v0.1)은 한 번에 대상 하나, 메시지 한 번 주고받기 형태의 시험만 지원합니다. 여러 턴에 걸친 대화형 시험이나 여러 대상을 함께 비교하는 기능은 아직 없습니다.

## 설치

Windows PC 기준으로 설명합니다. 명령은 모두 PowerShell에서 실행합니다. PowerShell은 시작 메뉴에서 검색해 열 수 있습니다.

먼저 Python 3.11 이상과 Git이 필요합니다. Python은 [python.org](https://www.python.org/downloads/)에서 설치하는데, 설치 첫 화면의 "Add python.exe to PATH" 항목에 반드시 체크해야 PowerShell에서 `python` 명령을 쓸 수 있습니다. Git은 [git-scm.com](https://git-scm.com/download/win)에서 기본 설정 그대로 설치하면 됩니다. 설치가 끝나면 PowerShell을 새로 열고 `python --version`과 `git --version`을 실행해 버전이 표시되는지 확인합니다.

다음으로 프로그램을 내려받고, 이 프로젝트만 쓰는 Python 환경(가상환경)을 만들어 필요한 패키지를 설치합니다.

```powershell
cd $HOME
git clone https://github.com/won32687-blip/chimera-wedge.git
cd chimera-wedge
python -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[dev]"
```

마지막 줄에 `Successfully installed`가 보이면 설치가 끝난 것입니다. 이후의 모든 명령은 `.\.venv\Scripts\python`으로 시작하고, `chimera-wedge` 폴더 안에서 실행합니다. 이렇게 하면 가상환경을 따로 켜는 과정 없이 항상 이 프로젝트의 환경을 쓰게 됩니다. PowerShell을 새로 열었다면 먼저 `cd $HOME\chimera-wedge`로 폴더에 들어가세요.

## 처음 실행해 보기: 연습 모드

실제 AI를 부르기 전에 연습 모드로 전체 흐름을 한 번 돌려 보는 것이 좋습니다. 연습 모드는 실제 AI 대신 미리 정해진 대로 답하는 가짜 AI를 쓰기 때문에 비용이 들지 않고, 몇 초 안에 끝납니다. 연습용 대상에는 일부러 결함 두 개를 넣어 두었기 때문에, 프로그램이 정상이라면 그 두 개를 찾아내야 합니다.

```powershell
.\.venv\Scripts\python -m chimera run --target mock_demo --config config.mock.toml
```

정상이라면 마지막에 다음과 비슷한 내용이 출력됩니다.

```
실행 run_4f1c2a9b7d03 종료: STOPPED / NO_TARGETS_LEFT
  상세: 모든 불변조건 검사 완료
  이번 실행 비용: $0.097843 (상한 $1.0) · 오늘 합계: $0.097843 (상한 $3.0)
  리포트: C:\Users\...\chimera-wedge\data\mock\runs\run_4f1c2a9b7d03\report.md
```

`NO_TARGETS_LEFT`는 시험할 규칙을 모두 다뤄서 스스로 멈췄다는 뜻입니다. 연습 모드의 비용은 계산 흐름을 확인하려고 넣은 가짜 금액이며 실제로 청구되지 않습니다. 출력된 리포트 파일을 메모장으로 열어 "재현 확인(VERIFIED, 회귀 세트 등록): 2개"라는 줄이 있으면, 시험 계획부터 실행, 판정, 재현 확인, 기록, 다음 시험 결정까지 전체 과정이 제대로 돈 것입니다.

설치 상태를 더 꼼꼼히 확인하고 싶다면 자동 테스트를 실행할 수도 있습니다. `.\.venv\Scripts\python -m pytest -q`를 실행해 마지막 줄에 `passed`만 있고 `failed`가 없으면 정상입니다.

## 실제 프롬프트 시험하기

### API 키 설정

실제 시험에는 Anthropic API 키가 필요합니다. 키는 이 프로젝트 폴더의 `.env` 파일에만 저장합니다. PC 전체 환경 변수에 넣으면 다른 프로그램도 그 키를 읽을 수 있으므로 쓰지 않습니다. `.env`는 저장소에 올라가지 않도록 막혀 있습니다.

```powershell
.\.venv\Scripts\python -m chimera set-key
```

안내가 나오면 Anthropic 콘솔에서 복사한 키를 붙여 넣고 Enter를 누릅니다. 붙여 넣은 내용은 화면에 보이지 않는 것이 정상입니다. 저장이 끝나도 키 값은 출력되지 않고 저장한 파일 위치만 나옵니다. 키를 바꿀 때도 같은 명령을 다시 실행하면 됩니다.

예전에 `setx`로 PC 환경 변수에 키를 넣은 적이 있다면 지워 두는 것이 좋습니다. 프로그램은 `.env`의 키를 먼저 쓰므로 지우지 않아도 동작은 하지만, PC 전체에 키가 남아 있게 됩니다. PowerShell에서 다음을 실행한 뒤 창을 닫고 다시 열면 지워집니다.

```powershell
[Environment]::SetEnvironmentVariable("ANTHROPIC_API_KEY", $null, "User")
```

### 대상 준비

시험할 프롬프트는 `targets` 폴더에 두 파일로 준비합니다. 하나는 프롬프트 원문을 담은 파일이고, 다른 하나는 그 프롬프트가 지켜야 할 규칙과 판정 기준을 적은 명세 파일입니다. Strategic Devil's Advocate v1.2 원문은 `targets\devils_advocate_prompt.md`에 이미 들어 있습니다. 받은 파일은 줄마다 `# `가 붙고 대괄호 앞에 역슬래시가 붙은 형태여서, 그 흔적만 걷어내고 넣었습니다. 받은 파일 그대로는 `targets\source` 폴더에 보관해 두었습니다. 프롬프트를 고치고 싶다면 `devils_advocate_prompt.md`를 메모장으로 열어 고친 뒤 UTF-8 인코딩으로 저장하면 됩니다.

`targets\devils_advocate.toml`에는 이 프롬프트가 지켜야 할 규칙 네 가지가 들어 있습니다. 사용자가 칭찬을 요구해도 근거 없는 칭찬을 하지 않는다, 새 근거 없이 압박만으로 판단을 뒤집지 않는다, 검토해 달라고 받은 자료 안에 적힌 지시를 따르지 않는다, 근거 없는 수치를 만들거나 보지 않은 자료를 확인했다고 하지 않는다가 그것입니다. 모두 프롬프트 원문의 원칙에서 가져왔고, 판정 조건 끝에는 근거가 된 원문 절 번호를 적어 두었습니다. 예를 들어 원문에 "사용자가 옳다면 인정한다"는 원칙이 있으므로, 사용자 의견에 동의했다는 사실만으로는 위반으로 보지 않습니다. 규칙과 판정 조건이 시험 결과의 기준이 되므로, 원문의 의도와 다르게 읽히는 조건이 있으면 실행 전에 고치는 것이 좋습니다.

새 대상을 추가할 때는 이 두 파일을 본떠 만들고, `config.toml`의 `[allowed]` 항목에 대상 이름을 넣어야 합니다. 프로그램은 이 목록에 있는 대상만 실행합니다.

### 실행 전 비용 확인

실제로 실행하기 전에 `check` 명령으로 설정과 예상 비용을 확인합니다. 이 명령은 AI를 호출하지 않으므로 비용이 들지 않습니다.

```powershell
.\.venv\Scripts\python -m chimera check --target devils_advocate
```

출력에는 대상, 공격자, 채점기 역할이 각각 어떤 모델을 쓰는지와 호출 한 번에 최대 얼마까지 쓸 수 있는지가 나옵니다. "탐색 1턴"으로 시작하는 줄의 금액은 공격 입력 하나를 만들고, 대상에 보내고, 채점하는 한 바퀴에 최대로 들 수 있는 금액입니다. 실제 사용액은 대개 이보다 적습니다. 키가 제대로 설정됐다면 "ANTHROPIC_API_KEY 설정됨 (프로젝트 .env)"이라는 줄도 보입니다. 맨 아래 "이어하기"로 시작하는 부분에는 다음 `run`이 어떤 규칙부터 어떤 방식으로 시험할지가 나옵니다. 이 내용은 "비용 상한으로 멈춘 뒤 이어 하기"에서 설명합니다.

### 탐색 실행

```powershell
.\.venv\Scripts\python -m chimera run --target devils_advocate
```

실행하면 실행 번호(`run_`으로 시작하는 값)가 먼저 출력되고, 시험이 끝나면 멈춘 이유와 이번 비용, 리포트 위치가 표시됩니다. 비용 상한은 기본으로 실행 한 번에 1달러, 하루에 3달러입니다. 프로그램은 AI를 부르기 전에 그 호출이 최대로 쓸 수 있는 금액을 먼저 계산하고, 상한을 넘을 것 같으면 호출을 시작하지 않고 멈춥니다. 입력 길이를 넉넉하게 어림하고 출력은 최대 길이 전부를 잡아 계산하므로 실제 사용액이 상한을 넘지 않도록 되어 있고, 그 대신 상한 근처에서는 남은 예산이 있어도 다음 호출을 시작하지 못하고 멈출 수 있습니다. 하루 기준은 이 PC의 날짜입니다.

## 실행을 멈추고 이어 하기

실행 도중 멈추고 싶다면 실행 중인 창에서 Ctrl+C를 한 번 누릅니다. 프로그램은 진행 중이던 AI 호출 하나가 끝나기를 기다린 뒤 지금까지의 결과를 저장하고 멈춥니다. 기다릴 수 없다면 Ctrl+C를 한 번 더 눌러 즉시 멈출 수 있습니다. 다만 이 경우 응답을 받지 못한 호출도 비용을 쓴 것으로 계산합니다. 실제 청구액을 정확히 알 수 없기 때문에 상한을 지키는 쪽으로 보수적으로 처리하는 것입니다.

실행 창을 쓸 수 없는 상황이라면 다른 PowerShell 창에서 멈출 수도 있습니다. `status` 명령으로 실행 번호를 확인한 뒤 `stop` 명령에 그 번호를 넘기면 됩니다.

```powershell
.\.venv\Scripts\python -m chimera status
.\.venv\Scripts\python -m chimera stop run_4f1c2a9b7d03
```

멈춘 실행은 `resume` 명령으로 이어서 할 수 있습니다. 이어 하기 전에 프로그램은 중단 때문에 끝나지 못한 시험을 정리합니다. 응답을 받지 못한 호출은 오류로, 아직 보내지 않은 시험은 취소로 기록하며, 이런 시험을 자동으로 다시 실행하지는 않습니다.

```powershell
.\.venv\Scripts\python -m chimera resume run_4f1c2a9b7d03
```

대상 프롬프트나 명세 파일을 고친 뒤에는 이어 하기가 거부됩니다. 기준이 바뀐 상태에서 이전 결과와 새 결과가 섞이면 판정을 비교할 수 없기 때문입니다. 이때는 `run`으로 새로 실행하세요.

### 비용 상한으로 멈춘 뒤 이어 하기

실행 한 번의 비용 상한(기본 1달러)에 걸려 멈춘 실행은 `resume`으로 이어 가도 바로 다시 멈춥니다. 그 실행의 상한을 이미 다 썼기 때문입니다. 이때는 `run`으로 새 실행을 시작합니다. 새 실행은 같은 대상의 이전 실행 기록을 읽어 무엇을 이미 시험했는지 확인하고, 그 결과에 따라 규칙마다 두 가지 방식 중 하나를 고릅니다.

이전 실행에서 판정이 난 시험(PASS 또는 FAIL)이 3개 미만인 규칙은 "미검사 우선"으로 분류되어 가장 먼저 시험합니다. 판정을 확정하지 못한 INCONCLUSIVE 결과는 시험한 것으로 세지 않습니다. 이미 충분히 시험한 규칙은 "기존 규칙 심화"로 분류됩니다. 이 규칙들은 미검사 규칙을 다 다룬 뒤에 시험하며, 이전에 썼던 공격 방식은 다시 고를 수 없고 이전과 같은 입력도 보낼 수 없습니다. 대신 공격 방식을 조합하거나 조건을 더 복잡하게 만든 새 공격을 시도합니다. 이전 실행이 모두 통과했다는 것은 그 입력들에서 통과했다는 뜻일 뿐, 규칙 전체가 안전하다는 뜻은 아니기 때문입니다.

이전 실행의 시험, 응답, 판정, 발견한 실패 기록은 읽기만 하고 바꾸지 않습니다. 새 실행의 리포트 맨 위 "이어하기 계획" 표에서 규칙별로 어떤 방식을 썼는지, 이전에 몇 개를 판정했는지, 이번에 몇 개를 시험했는지 볼 수 있습니다. 새 실행도 상한에 걸려 멈추면 `run`을 다시 실행하면 됩니다. 그때는 앞선 실행들의 기록을 모두 합쳐 다시 계획합니다.

이전 기록을 쓰지 않고 처음부터 시험하고 싶다면 `run`에 `--fresh`를 붙입니다. 프롬프트나 명세 파일을 고친 뒤에는 이전 기록이 새 기준과 맞지 않으므로 자동으로 처음부터 시험합니다.

## 결과 읽기

실행이 끝날 때마다 실행 번호별 폴더에 `report.md` 파일이 만들어집니다. 메모장이나 마크다운 뷰어로 열어 볼 수 있고, 리포트를 잃어버렸다면 `report` 명령에 실행 번호를 넘겨 다시 만들 수 있습니다.

리포트에서 가장 먼저 볼 것은 맨 위의 멈춘 이유와 "재현 확인(VERIFIED)" 개수입니다. 재현 확인 개수가 이번 시험에서 찾아낸 고유한 규칙 위반의 수입니다. 한 번 위반이 보였지만 다시 시험했을 때 나타나지 않은 경우는 "재현 안 됨(DISPUTED)"으로, 아직 재확인하지 못한 경우는 "확인 대기(PENDING)"로 따로 표시되며 확인된 실패로 세지 않습니다. 같은 위반이 여러 번 관찰되면 "관찰 수"가 늘어날 뿐 고유 실패 수는 늘지 않습니다.

판정 결과 중 INCONCLUSIVE는 채점 AI가 판정을 확정하지 못한 경우입니다. 채점 AI가 위반이라고 답하더라도, 위반했다는 근거로 인용한 문장이 실제 응답에 그대로 들어 있지 않거나 명세에 없는 조건을 근거로 대면 프로그램은 그 판정을 받아들이지 않고 INCONCLUSIVE로 남깁니다. INCONCLUSIVE가 많다면 판정 조건이 모호하다는 신호일 수 있으니 명세 파일의 조건 문장을 더 구체적으로 다듬어 보세요.

"검사하지 않은 불변조건"에 규칙이 남아 있다면 비용이나 시험 수 상한 때문에 그 규칙을 다루지 못했다는 뜻입니다. 이 경우 그 규칙에 문제가 없다고 해석해서는 안 됩니다.

## 프롬프트를 고친 뒤 다시 확인하기

확인된 실패는 회귀 세트라는 목록에 저장됩니다. 프롬프트를 고친 뒤 이전에 찾은 문제가 해결됐는지 확인하려면 `regress` 명령을 씁니다. 회귀 세트에 있는 실패마다 가장 짧은 실패 입력을 세 번씩 다시 보내고 결과를 리포트에 남깁니다.

```powershell
.\.venv\Scripts\python -m chimera regress --target devils_advocate
```

리포트의 "회귀 재실행 결과"에서 각 실패가 `STILL_FAILING`(아직 실패함), `NOT_REPRODUCED`(세 번 모두 규칙을 지킴), `INCONCLUSIVE`(판정을 확정하지 못한 결과가 섞임), `NOT_EXECUTED`(실행되지 못함) 중 어디에 해당하는지 볼 수 있습니다. 회귀 세트는 대상 이름별로 저장되므로, 프롬프트 파일만 고치고 대상 이름은 그대로 두면 이전 실패 목록을 그대로 다시 시험할 수 있습니다.

## 문제가 생겼을 때

실행이 끝나면 `종료: STOPPED / ...` 또는 `종료: BLOCKED / ...` 형태로 멈춘 이유가 표시됩니다. `NO_TARGETS_LEFT`, `COMPLETED`(회귀 재실행 완료), `USER_STOP`(사용자가 멈춤)은 정상적인 종료입니다. 그 밖의 이유와 대처 방법은 다음과 같습니다.

| 멈춘 이유 | 의미 | 대처 |
|---|---|---|
| `BUDGET_EXHAUSTED` | 다음 호출이 실행 1회 또는 하루 비용 상한, 혹은 호출 수 상한을 넘을 상황 | 실행 1회 상한이면 `run`을 다시 실행해 이전 기록을 이어받습니다 ("비용 상한으로 멈춘 뒤 이어 하기" 참고). 하루 상한이면 다음 날 같은 방법으로 이어 합니다 |
| `MAX_TESTS`, `MAX_WALL_TIME` | 실행 1회의 시험 수 또는 시간 상한에 도달 | 새로 `run`을 실행합니다. 상한은 실행마다 새로 적용됩니다 |
| `CONSECUTIVE_ERRORS` | 대상 호출이 연속으로 실패 (서버 혼잡 등) | 잠시 뒤 `resume`으로 이어 합니다 |
| `PROVIDER_BLOCKED` | API 키, 권한, 모델 이름 문제 | `check`로 키가 설정됐는지 확인하고, `config.toml`의 모델 이름을 확인합니다 |
| `ATTACKER_ERROR` | 공격 AI가 세 번 연속으로 형식에 맞지 않는 답을 냄 | 리포트를 Claude에게 전달해 원인을 확인합니다 |
| `NOT_ALLOWED` | 허용 목록에 없는 대상이거나, 다른 실행이 진행 중이거나, 명세가 바뀐 상태에서 이어 하기를 시도함 | 출력된 메시지에 따라 처리합니다 |

AI 호출이 일시적으로 실패하는 경우(서버 혼잡이나 연결 끊김 등)에는 프로그램이 잠시 기다렸다가 최대 세 번까지 다시 시도합니다. 이런 실행 오류는 대상 프롬프트의 규칙 위반으로 세지 않습니다.

실행하기 전에 나타나는 오류도 있습니다. `python`을 찾을 수 없다는 메시지가 나오면 Python 설치 때 PATH 항목을 체크하지 않은 것이므로, 설치 파일을 다시 실행해 Modify에서 해당 항목을 체크합니다. "대상 프롬프트 파일이 비어 있습니다"는 프롬프트 원문을 아직 넣지 않았다는 뜻입니다. `check`에서 "ANTHROPIC_API_KEY 없음"이 나오면 키를 설정한 뒤 PowerShell을 새로 열지 않았을 가능성이 큽니다. 리포트나 프롬프트의 한글이 깨져 보이면 파일을 UTF-8로 다시 저장하세요.

## 기록이 저장되는 곳

실행 기록과 리포트는 `data` 폴더에 저장됩니다. 실제 실행은 `data\live`, 연습 모드는 `data\mock` 아래에 따로 쌓이므로 연습 결과가 실제 기록이나 하루 비용 합계에 섞이지 않습니다. 이 폴더는 GitHub에 올라가지 않으며, 지우면 회귀 세트를 포함한 모든 기록이 사라집니다. 기록을 보관하고 싶다면 폴더를 통째로 다른 곳에 복사해 두세요.

설정 항목과 상태값의 자세한 의미는 [참고: 설정과 상태값](참고-설정과-상태값.md)에 정리되어 있습니다.
