# 운영·개발 가이드

AI(Claude·Codex 등)에게 개발을 맡기고, 검증 결과를 반영하고, 프로젝트 상태를 관리하는 방법. 코딩 AI가 지켜야 할 규칙의 원본은 [`CLAUDE.md`](../../CLAUDE.md)이고, 이 문서는 사람이 그 흐름을 운영하는 쪽에서 정리한 것이다.

## 1. 문서 지도

| 문서 | 독자 | 언제 갱신 |
|---|---|---|
| `docs/guide/` | 프로그램 사용자 | 사용 방법이 바뀔 때 ([작성 원칙](../문서-작성-원칙.md) 적용) |
| `CLAUDE.md` | 코딩 AI | 작업 규칙이 바뀔 때 |
| `docs/state/PROJECT_STATE.md` | 사람·AI | 단계가 바뀌거나 결정이 확정될 때 |
| `docs/state/backlog.md` | 사람·AI | 미룬 결정·기능이 생길 때 |
| `docs/HANDOFF.md` | 다음 세션의 AI | 작업 단위가 끝날 때, 대화를 새로 시작하기 전 |
| `docs/verifier-coverage.md` | 사람·AI | 판정 기능을 추가·변경할 때 |

## 2. AI에게 작업을 맡길 때

요청에 넣으면 좋은 것:
- 목표 한 줄 (무엇이 되면 끝인가)
- 확정된 결정과 바꾸면 안 되는 것
- 실제 API 호출 허용 범위 (기본: 1회 시험 호출까지만)

AI가 지켜야 하는 흐름 (CLAUDE.md 3·4절):
1. `main` 최신화 → 새 브랜치
2. 수정 전에 바뀌는 위치를 `WEDGE → EXECUTOR → VERIFIER → CODEX` 중에서 밝힌다
3. 수정 → `python -m pytest -q` → 결과 원문 보고
4. 루프 동작이 바뀌면 Mock 실행 결과도 보고
5. PR (흐름 카드, 사람 확인 필요 여부, 사람이 직접 확인할 것 3가지)
6. CI 통과 확인 → 사용자에게 병합 요청. **병합은 사용자만 한다**

AI가 멈추고 먼저 물어야 하는 것:
- [ ] 상태 축·판정 규칙·재현 규칙 변경
- [ ] DB 스키마 변경
- [ ] 예산·중단 로직을 약하게 바꾸는 변경
- [ ] 대상 명세의 불변조건·판정 조건 변경
- [ ] `.github/workflows/` 변경
- [ ] 실제 API를 2회 이상 호출하는 실행 (먼저 `chimera check`의 예상 비용 보고)

## 3. PR 검토 체크리스트

- [ ] CI가 Ubuntu·Windows 모두 초록인가
- [ ] PR 설명의 "사람이 직접 확인할 것 3가지"를 직접 해 봤는가
- [ ] 근거 표시가 있는가: (사용자 확정) (실행 기록) (코드 확인) (AI 생성, 미검증) (미확인)
- [ ] 실제 API 호출 횟수·비용이 적혀 있는가
- [ ] 사용자 가이드에 영향이 있는 변경이면 `docs/guide/`도 함께 고쳤는가

## 4. 검증 결과를 반영할 때

실제 실행 후 리포트를 받으면:

1. 멈춘 이유가 정상 종료(`NO_TARGETS_LEFT`·`COMPLETED`·`USER_STOP`)인지 확인
2. `INCONCLUSIVE`가 많으면 판정 조건 문장이 모호하다는 신호 → 대상 명세 조건을 다듬는다 (사용자 확정 필요)
3. `INVALID`가 나오면 대상 문제가 아니라 판정 기준 오류 → 명세 수정
4. 확인된 실패(VERIFIED)는 프롬프트 수정 후보 → 프롬프트 수정 → `chimera regress`로 재확인
5. 비용 실측값을 `PROJECT_STATE.md`에 기록하고, 상한 조정이 필요하면 backlog에 결정 대기로 올린다

```powershell
.\.venv\Scripts\python -m chimera status
.\.venv\Scripts\python -m chimera report run_4f1c2a9b7d03
.\.venv\Scripts\python -m chimera regress --target devils_advocate
```

## 5. 상태 관리와 인계

- 새 작업을 시작하는 AI는 `PROJECT_STATE.md` → `HANDOFF.md` 순서로 읽는다.
- 상태 문서와 실제(코드·GitHub)가 다르면 AI는 고치지 말고 보고한다.
- 대화가 길어지면: `HANDOFF.md`의 "지금 상태", "사용자가 해 줄 것", "열린 질문"을 갱신하고 새 대화를 시작한다.
- 미룬 결정은 `backlog.md`의 "결정 대기"에 두고, 정할 시점이 오면 AI가 꺼내서 묻는다.

## 6. 개발자용 빠른 명령

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
python -m chimera run --target mock_demo --config config.mock.toml
python -m chimera check --target devils_advocate
```

코드 구조: `chimera/controller.py` 루프 제어, `wedge.py` 공격 AI 호출·출력 검사, `executor.py` 모든 모델 호출(허용 검사·예산·재시도·중단), `verifier.py` 판정, `codex.py` 기록·중복·재현, `report.py` 리포트, `cli.py` 명령. 모델 교체 계층은 `chimera/providers/`.
